How DASM prompt embeddings work

PC bake → git → Pi pull. No MGA-CLAP on the collector.

← ML Settings
DASM open-vocab labels are edited in the app, but the query vectors that the Pi needs are baked on a separate machine (your PC), committed to git, then pulled onto the Pi. That keeps the heavy text encoder (MGA-CLAP / BERT) off the Raspberry Pi so runtime stays ONNX + numpy only.

CLAP can rebuild embeddings in the browser because its text tower is a small ONNX model already on the Pi. DASM’s text tower is far larger, so we never ship it with the collector. Changing a prompt without re-baking leaves the sync badge out of sync until you run the bake script and pull the new config/dasm_query_embeddings.npz.

Step by step

1

Pi Edit and save prompts

Open Settings → Heavy ML → DASM. Add or change label / prompt rows, then Save prompts. That writes config/dasm_prompts.json on the Pi.

  • Use clear short labels (shown on charts).
  • The prompt text is what MGA-CLAP will encode (e.g. sound of siren).
  • At most 16 prompts — ONNX is exported with a fixed 16-slot budget; fewer prompts are zero-padded at inference.
  • Saving alone does not update embeddings — expect “Bake on PC, then pull” until step 4.
2

PC Sync the prompts file to your bake machine

Get the updated config/dasm_prompts.json onto the PC that has the Phase 0 spike tree (Transformer4SED + MGA-CLAP + htast_mga.pt). Common options:

  • Commit/push from the Pi (or copy the file), then pull on the PC; or
  • Edit the same JSON on the PC if that checkout is already the source of truth.

You need the spike once for baking — the product venv on the Pi is not enough for this step.

3

PC Bake embeddings

From the urban-sound-collector repo, run the product bake script with the spike interpreter (it has torch / MGA-CLAP): 

/path/to/Transformer4SED/.venv/bin/python scripts/bake_dasm_embeddings.py \
  --spike-root /path/to/Transformer4SED

That reads config/dasm_prompts.json and writes config/dasm_query_embeddings.npz (small file, safe to commit). Optional dry-run without loading the model: 

python scripts/bake_dasm_embeddings.py --check
4

PC Commit and push

Version the prompts and embeddings together so they stay in sync:

git add config/dasm_prompts.json config/dasm_query_embeddings.npz
git commit -m "Update DASM prompt embeddings"
git push
5

Pi Pull and run

On the Pi:

cd ~/urban-sound-collector   # your checkout path
git pull

Refresh Settings → DASM. The badge should show Embeddings in sync and ONNX ready (after the one-time model install below). Then Start → Heavy ML: DASM.

One-time on the Pi (models)

★

Install ONNX + base queries

Embedding bake does not install the SED graph. Once per device, copy from the spike export into models/dasm/ (gitignored — large files): 

mkdir -p models/dasm
cp …/onnx_export/dasm_text_fp32.onnx models/dasm/
cp …/base_query.npy models/dasm/
# optional: bn0.npz for mel parity

Details: models/README.md and docs/DASM-SPIKE.md. Also ensure onnxruntime is in the Pi product venv.

Checklist when something looks wrong
• Badge “Bake on PC, then pull” → prompts hash ≠ embeddings; re-bake and pull.
• “ONNX missing” → models/dasm/dasm_text_fp32.onnx or base_query.npy not installed.
• Start fails with exclusive heavy ML → CLAP and DASM cannot both be on; pick one.
• Bake fails missing spike → set --spike-root or DASM_SPIKE_ROOT to the Transformer4SED tree.
